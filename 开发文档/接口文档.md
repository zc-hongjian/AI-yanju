# 接口文档

> 适用版本：当前 `main`（FastAPI + LangGraph 研究助手 MVP）
> 后端入口：[`web.py`](../web.py)（默认 `http://127.0.0.1:8000`）
> 前端消费方：[`index.html`](../index.html)（主界面）、[`launch.html`](../launch.html)（启动页）

## 1. 通用约定

| 项 | 说明 |
| --- | --- |
| Base URL | `http://127.0.0.1:8000`（端口可用 `AGENT_WEB_PORT` 修改） |
| 协议 | HTTP/1.1；研究类接口支持 NDJSON 流式响应 |
| 认证 | 无登录/无鉴权（仅本机演示用，**不要暴露公网**） |
| 请求体 | `Content-Type: application/json` |
| 响应体 | 普通接口为 JSON；`*/stream` 为 `application/x-ndjson`，一行一个 JSON 事件 |
| 错误格式 | `{"detail": "错误说明"}`，HTTP 状态码 400 / 404 / 500 |
| 会话标识 | `thread_id`（形如 `web-1a2b3c4d`），所有会话相关接口用它定位 |
| 追踪标识 | `trace_id`（8 位 hex），用于 `/api/trace/{trace_id}` 与日志文件名 |

## 2. 页面路由（返回 HTML，不参与前端 API 调试）

| 方法 | 路径 | 返回 |
| --- | --- | --- |
| GET | `/` | 一键启用启动页 `launch.html` |
| GET | `/launch` | 同上（启动页别名） |
| GET | `/index.html` | 主界面 `index.html` |
| GET | `/app` | 主界面别名（等价 `/index.html`） |

## 3. 流式协议（`/api/research/stream`、`/api/resume/stream`）

响应头 `Content-Type: application/x-ndjson`，**每行一个 JSON**，按顺序可能出现四类事件：

```jsonc
{"type":"start","thread_id":"web-1a2b3c4d","trace_id":"1a2b3c4d"}
{"type":"log","entry":{ /* 结构化日志，见下 */ "step_id":"S001","node_name":"receive_question","tool_name":"","status":"ok","retry_count":0,"latency_ms":0,"input_summary":"…","output_summary":"…","error":null,"timestamp":"2026-11-14T09:30:00+08:00","trace_id":"1a2b3c4d" }}
{"type":"result","data":{ /* 见 4.2 响应结构 */ }}
// 或（本次运行异常，后端仍存活）
{"type":"error","message":"RuntimeError: …"}
```

约定：

1. **第一行一定是 `start`**，前端据此拿到 `thread_id`；中途断流时才能给对应会话标“已中断”；
2. `log` 事件可能很多条，前端按 `step_id` 去重追加；
3. 正常结束最后一行是 `result`；后端主动报错最后一行是 `error`；
4. 连接被断开（后端退出/网络断）时不会再有 `error`，前端要把「没收到 result」当**中断**处理。

## 4. 研究接口

### 4.1 `POST /api/research` — 启动一次研究（阻塞版）

请求：

```json
{ "question": "LangGraph 如何实现人工中断？", "parent_thread_id": "web-xxxx（可选，多轮追问）" }
```

- `question` 必填，去掉首尾空白后不能为空，否则 `400 {"detail":"研究问题不能为空"}`；
- `parent_thread_id` 可选：读取父会话结论摘要（≤1200 字符）注入本轮 `history_context`。

响应（`_pack` 包装）：

```json
{
  "thread_id": "web-1a2b3c4d",
  "status": "interrupt",
  "interrupt": { "type": "draft_review", "draft_report": "…", "…": "…" },
  "logs": [ { "step_id": "S001", "…": "…" } ],
  "final_output": null
}
```

- `status`：`interrupt`（停在人工确认点）或 `completed`（跑完）；
- `interrupt`：人工确认载荷，结构见 §7；无中断时为 `null`；
- `final_output`：最终结果（报告、来源、证据、覆盖率、token/成本等），无中断时返回，否则 `null`。

### 4.2 `POST /api/research/stream` — 启动一次研究（流式版）

请求同 4.1，响应为 §3 的 NDJSON 流；`result.data` 与 4.1 响应结构一致。

### 4.3 `POST /api/resume` — 提交人工确认（阻塞版）

```json
{ "thread_id": "web-1a2b3c4d", "value": { "decision": "approve", "comment": "" } }
```

- `thread_id` 必填，不存在返回 `400 {"detail":"缺少 thread_id"}` 或恢复失败 `500`；
- `value` 结构随当前中断类型变化，见 §7；返回结构与 4.1 相同（下一次中断或最终结果）。

### 4.4 `POST /api/resume/stream` — 提交人工确认（流式版）

请求同 4.3，响应 NDJSON；服务重启后仍可用（`trace_id` 从 `sessions` 索引回源）。
若会话不存在：`400 {"detail":"会话不存在（可能已过期或从未创建）"}`。

## 5. 会话接口

### 5.1 `GET /api/sessions?limit=20`

```json
{
  "sessions": [
    {
      "thread_id": "web-1a2b3c4d",
      "trace_id": "1a2b3c4d",
      "question": "LangGraph 如何实现人工中断？",
      "status": "interrupt",
      "parent_thread_id": "",
      "created_at": "2026-11-14T09:30:00+08:00",
      "updated_at": "2026-11-14T09:32:10+08:00"
    }
  ],
  "count": 1,
  "enabled": true
}
```

`limit` 范围 1~100（默认 20）；`enabled=false` 表示会话索引库不可用（不影响研究主流程）。
`status` 取值见 §8.2。

### 5.2 `GET /api/sessions/{thread_id}`

返回与 4.1 同构的数据，另附会话元信息：

```json
{
  "thread_id": "web-1a2b3c4d",
  "status": "interrupt",
  "interrupt": { "type": "draft_review", "…": "…" },
  "logs": [],
  "final_output": null,
  "question": "…",
  "trace_id": "1a2b3c4d",
  "parent_thread_id": "",
  "created_at": "…",
  "updated_at": "…",
  "recoverable": true
}
```

- 会话不存在：`404 {"detail":"会话不存在"}`；
- 若 checkpoint 已损坏但索引仍在，会退回索引表信息。

### 5.3 `POST /api/sessions/{thread_id}/interrupt`

前端检测到流中断（后端退出/断网）时调用，把仍在 `running` 的会话标成 `interrupted`。

响应：`{"ok": true, "thread_id": "web-…", "status": "interrupted"}`；会话不存在 `404`。

### 5.4 `DELETE /api/sessions/{thread_id}`

删除单条历史会话：**会话索引行 + 该 thread 的 checkpoint/writes 行**（`logs/` 与 trace 保留做审计）。

```json
{ "ok": true, "thread_id": "web-1a2b3c4d",
  "removed": { "sessions": 1, "checkpoints": 18, "writes": 42 } }
```

会话不存在：`404 {"detail":"会话不存在"}`；`removed` 是各表实际删除行数。

## 6. 可观测性接口

### 6.1 `GET /api/trace/{trace_id}`

```json
{
  "trace_id": "1a2b3c4d",
  "spans": [
    {
      "type": "span", "trace_id": "1a2b3c4d", "span_id": "draft_report-1731…",
      "node": "draft_report", "started_at": "2026-11-14T09:31:02.123+08:00",
      "latency_ms": 14129, "status": "ok", "attempt": 1, "model": "glm-4-flash",
      "prompt_tokens": 3200, "completion_tokens": 900, "total_tokens": 4100,
      "calls": 5, "cost_cny": 0.0, "cost_estimated": false, "error": null
    }
  ],
  "summary": { "status": "completed", "duration_ms": 138690, "model": "glm-4-flash",
               "total_tokens": 4511, "cost_cny": 0.0, "node_count": 14,
               "token_usage_by_node": {}, "cost_by_node": {} },
  "span_count": 14
}
```

不存在：`404 {"detail":"trace 不存在（可能未开启或已被清理）"}`。

### 6.2 `GET /api/cost/summary?days=7`

```json
{
  "days": 7,
  "totals": { "runs": 3, "calls": 120, "prompt_tokens": 50000,
              "completion_tokens": 12000, "total_tokens": 62000,
              "cost_cny": 0.06, "estimated_runs": 1 },
  "by_model": [ { "model": "glm-4-flash", "runs": 2, "cost_cny": 0.0, "…": "…" } ],
  "by_day": [ { "date": "2026-11-14", "runs": 2, "cost_cny": 0.0, "…": "…" } ]
}
```

`days` 范围 1~90。

## 7. 人工确认载荷（`interrupt` 字段 / `resume.value` 结构）

### 7.1 草稿审核（`type: "draft_review"`）

```json
{
  "type": "draft_review",
  "research_question": "…",
  "draft_report": "## 摘要 …（Markdown）",
  "sources": [ { "url": "https://…", "title": "…" } ],
  "evidence_count": 12,
  "revision_count": 0,
  "coverage_summary": { "total": 5, "covered": 2, "rate": 0.4, "uncovered": ["…"] },
  "verification": { "total": 12, "supported": 10, "partial": 2, "support_rate": 0.83 },
  "draft_review": { "status": "passed", "issues": [], "rewrites": 0, "checks": {} },
  "outline": ["摘要", "关键发现", "…"]
}
```

`resume.value` 三种：

| 决策 | 示例 |
| --- | --- |
| 通过 | `{"decision":"approve","comment":""}` |
| 修改（重新生成，最多 2 轮） | `{"decision":"revise","comment":"请补充局限部分"}` |
| 终止 | `{"decision":"terminate","comment":"方向不对"}` |
| 人工直接改稿（可选） | 同上再加 `"edited_report":"…完整 Markdown…"`，会过 URL 白名单清洗 |

### 7.2 发送邮件前（`type: "email_confirmation"`）

```json
{ "type": "email_confirmation", "research_question": "…",
  "email": { "to": "boss@example.com", "subject": "研究报告：…", "body": "…Markdown…" } }
```

`resume.value`：`{"send": true, "email_payload": {"to":"…","subject":"…","body":"…"}}` 或 `{"send": false}`。
收件人为空时跳过该动作并记录 `missing_email_to` 错误。

### 7.3 保存 Notion 前（`type: "notion_confirmation"`）

```json
{ "type": "notion_confirmation", "research_question": "…",
  "notion": { "title": "研究报告：…", "content": "…", "tags": ["research","ai-report"] } }
```

`resume.value`：`{"save": true, "notion_payload": {"title":"…","tags":["…"],"content":"…"}}` 或 `{"save": false}`。
标题为空时跳过。

## 8. 模型配置与健康检查

### 8.1 `GET /api/health`

```json
{ "status": "ok", "version": "0.3.0", "persistence": "sqlite",
  "checkpoint_db": "D:\\Build\\AI-hy\\data\\checkpoints.sqlite",
  "llm_mode": "openai", "model": "glm-4-flash", "configured": true }
```

### 8.2 `GET /api/config`（永远不含明文 Key）

```json
{ "configured": true, "mode": "openai", "model": "glm-4-flash",
  "base_url": "https://open.bigmodel.cn/api/paas/v4",
  "masked_key": "58c****fqWy", "source": "env" }
```

`source`：`runtime`（网页填写的内存配置）/ `env`（`.env`）/ `none`。

### 8.3 `POST /api/config`（保存到进程内存，不写 `.env`，重启失效）

请求：`{"api_key":"sk-…","base_url":"https://…/v1","model":"glm-4-flash"}`。
`api_key` 可留空表示沿用已保存的 Key；响应同 8.2。非法 Base URL → `400`。

### 8.4 `POST /api/config/test`（用请求里的配置做一次最小真实调用，不保存）

```json
{ "ok": true, "model": "glm-4-flash", "latency_ms": 812, "reply": "OK",
  "masked_key": "sk-****7890", "base_url": "https://…" }
```

失败：`400 {"detail":"连接失败：…（Key 已脱敏）"}`。

### 8.5 `DELETE /api/config`

清除运行时配置，回到启动时 `.env` 配置；响应同 8.2。

## 9. 状态与错误约定

### 9.1 会话状态（`sessions.sqlite.status`）

| 值 | 含义 |
| --- | --- |
| `running` | 正在执行（进程活着时才有可能出现） |
| `interrupt` | 停在人工确认点，可继续审批 |
| `completed` | 正常结束 |
| `interrupted` | 执行被中断（后端退出/断网/进程被杀），可重跑或删除 |
| `failed` | 本次运行在后端内部报错 |

启动时会把上一个进程遗留的 `running` 统一标成 `interrupted`。

### 9.2 常见 HTTP 错误

| 场景 | 状态码 | 示例 `detail` |
| --- | --- | --- |
| 研究问题为空 | 400 | `研究问题不能为空` |
| 缺少 thread_id | 400 | `缺少 thread_id` |
| 会话/trace 不存在 | 404 | `会话不存在` / `trace 不存在（可能未开启或已被清理）` |
| 恢复执行失败 | 500 | `恢复执行失败：…` |
| 配置校验失败 | 400 | `Base URL 必须是 http(s):// 开头的完整地址` |

## 10. 调用示例

```bash
# 1) 启动一次研究（阻塞，返回第一次中断）
curl -X POST http://127.0.0.1:8000/api/research \
  -H "Content-Type: application/json" \
  -d '{"question":"LangGraph 如何实现人工中断？"}'

# 2) 通过草稿审核（继续到邮件确认）
curl -X POST http://127.0.0.1:8000/api/resume \
  -H "Content-Type: application/json" \
  -d '{"thread_id":"web-1a2b3c4d","value":{"decision":"approve","comment":""}}'

# 3) 查看历史会话 / 删除
curl http://127.0.0.1:8000/api/sessions
curl -X DELETE http://127.0.0.1:8000/api/sessions/web-1a2b3c4d

# 4) 模型配置（Key 只进内存）
curl -X POST http://127.0.0.1:8000/api/config \
  -H "Content-Type: application/json" \
  -d '{"api_key":"sk-...","base_url":"https://api.deepseek.com/v1","model":"deepseek-chat"}'
```
