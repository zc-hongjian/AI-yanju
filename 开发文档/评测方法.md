# 评测方法（40 题测试集）

> 从 README 下沉的评测细节。最近一次结果与完整报告见 [eval_report.md](eval_report.md)；
> 数据集与脚本在 [`evaluation/`](../evaluation/)。

## 1. 数据集

[`evaluation/dataset.jsonl`](../evaluation/dataset.jsonl) 共 40 题，四类各 10 题：

| 类别 | 说明 | 例子 |
| --- | --- | --- |
| `fact` 简单事实 | 单点定义/现状 | LangGraph 是什么？ |
| `compare` 对比分析 | 两个对象差异 | LangGraph 和 AutoGen 在人工介入上的差异 |
| `timeliness` 时效性 | 需要较新信息 | 2025 年 AI Agent 企业落地进展 |
| `multi_hop` 多跳推理 | 需要组合多条证据 | 为什么中断必须配 checkpointer？ |

每题字段：`id`、`category`、`question`，可选 `expect_keywords`（预期要点，用于覆盖率代理指标）。

## 2. 三种评测模式

| 模式 | 命令 | 特点 | 能证明什么 |
| --- | --- | --- | --- |
| mock | `--mode mock` | 本地确定性搜索/抓取 fixture，不联网 | 流水线机制、引用、去重、延迟基线 |
| real | `--mode real` | 真实联网检索（LLM 仍可用离线启发式） | 检索质量、成功率、真实延迟 |
| real + llm | `--mode real --llm openai` | 真实联网 + 真实大模型（读 `.env`） | 端到端质量与真实 token/成本 |

```bash
# 流水线机制回归
python evaluation/run_eval.py --mode mock --tag mock_current
python evaluation/run_eval.py --mode mock --tag mock_p0
# 消融基线：关闭引用可点击化与问题拆解
python evaluation/run_eval.py --mode mock --tag mock_baseline --no-link-citations --no-sub-questions
# 真实联网（40 题，约 10~15 分钟）
python evaluation/run_eval.py --mode real --tag real_p0
# 真实联网 + 真实模型（先跑 check_llm.py；可先 --limit 10 试水）
python evaluation/run_eval.py --mode real --llm openai --tag real_llm --limit 10
# 汇总生成报告
python evaluation/make_report.py
```

可选参数：`--kb`（启用仓库知识库；默认关闭以保证评测可复现）、`--limit`、`--no-link-citations`、
`--no-sub-questions`。每次运行产物在 `evaluation/results/` 与 `evaluation/logs/`（gitignore）。

## 3. 指标定义

| 指标 | 口径 |
| --- | --- |
| 任务成功率 | `report` 非空、引用可追溯、无伪造来源、结构完整 |
| 引用可追溯率 | 报告中每个 `[S#]` 都能映射到本次抓取/知识库来源 |
| 关键结论可点击来源率 | `[S#]` 是否被转成可点击链接（HTML） |
| 工具调用正确率 | 是否按规划调用 `search_web`/`fetch_page`，参数合法 |
| 预期要点覆盖率 | 报告命中 `expect_keywords` 的比例（宽松代理） |
| 证据逐字可回溯率 | `quote` 是否逐字出现在抓取正文中 |
| 平均 / P95 延迟 | 单题端到端耗时 |
| 单任务成本 | 按 `config/pricing.json` 或 env 单价估算 |
| 来源去重率 | 去重后来源数 / 原始候选数 |
| 子问题拆解达标率 | 是否生成 3~5 个可独立检索的子问题 |
| **子问题证据覆盖率** | `quality.compute_coverage`：每个子问题被证据覆盖的比例 |
| **证据断言支持率** | `quality.verify_evidence`：claim 被 quote 支持（含 partial）的比例 |
| **平均检索轮次** | 首轮 + 补检轮数的平均值 |

## 4. 最近一次结果（`real_p0`，离线 LLM + 真实联网）

> 口径：**没有调用付费 LLM**（token/成本为 0），检索与抓取是真实联网；因此这组数字反映的是
> “检索 + 规则质量闭环”的水平，不是真实模型写作的质量。

| 指标 | 结果 |
| --- | --- |
| 任务成功率 | **85.0%** |
| 多跳类成功率 | 70.0% |
| 对比类成功率 | 70.0% |
| 引用可追溯 / 可点击 | **100% / 100%** |
| 工具调用正确率 | 90.0% |
| 事实覆盖（宽松代理） | 26.3% |
| 子问题证据覆盖率 | **51.2%**（未达 75% 目标） |
| 证据断言支持率 | **99.4%**（规则代理） |
| 平均检索轮次 | 1.68 |
| 平均 / P95 延迟 | 15.6s / 26.7s |

相比 `real_after_360` 基线：成功率 +2.5pp、多跳 +10pp、事实覆盖 +5pp。
完整表格、失败案例与消融见 [eval_report.md](eval_report.md)。

## 5. mock 流水线基线

确定性 fixture 下：任务成功率 **100%**（40/40）、引用可追溯/可点击 100%、子问题覆盖率 90.0%、
支持率 100%、平均检索轮次 1.15、平均 / P95 延迟 21ms / 25ms。

mock 只验证“流水线机制没坏”（搜索→抓取→证据→报告→引用→人工确认），不代表真实检索质量。

## 6. 已知口径限制

- 子问题覆盖率、断言支持率都是**规则代理指标**（词面/数字/实体/否定一致性），不是语义蕴含判断；
- 真实 LLM 全量评测仍需重跑（需要 API Key 与费用预算）；
- 失败主要集中在“对比题只抓到一方 / 站点 403 / JS 空页 / PDF 无法解析”，见 [OPTIMIZATION.md](OPTIMIZATION.md) 与评测报告。
